# nanoamp 0.1.6 — Windows 版

纳米孔 PCR 产物分析工具。给它一个 FASTQ 和一个目的序列，它告诉你这个样本里有
多少条序列是**完全正确**的、其余的长什么样、各占多少比例，并且（可选）把这些
变异翻译成**蛋白层面的后果**。

**不需要懂生信、不需要懂编程、不需要联网、不需要管理员权限，全程不使用
conda 也不使用 WSL。**

> **这一版相对 0.1.5 的主要变化：只改了 Windows 界面与安装器，分析核心未变**
> （R 包、模式 A/B/C 的算法与输出格式都与 0.1.5 相同；`nanoamp_0.1.0.tar.gz`
> 的字节内容与 0.1.5 一致，因此 0.1.5 已做过的分析侧验证依然有效）。
>
> 1. **修掉"注释页卡死"**：在「注释结果」里点一行后，联动筛选会重画该表，此前会把
>    选中状态弄丢，于是「查看蛋白序列…」与双击都会弹出一个**模态提示框**
>    （"请先在「注释结果」里选中一行"）；模态框占住窗口，看起来就是卡死。
>    现在重画后会恢复选中；双击改为打开**鼠标下那一行**；按钮在表格没有选中时

>    此前关掉功能注释再跑一次，界面会把上一次的注释连同**空计数**
>    （"已注释 个转录本…"）一起画成新结果；现在按本次 `qc.tsv` 判断，
>    并把"输出目录里还有上一次留下的文件，未显示"写在状态行与日志里。

>    （「运行日志」保留，它是本次会话的历史），上一次的结果留在内存里，可点
>    「查看上次结果」回看（再点回到本次结果），状态行标出那次的名称与时间。

>    定位安装目录，并把 `<安装目录>\bin\minimap2.exe` 固定交给 R（此前只在默认安装
>    位置生效，非默认安装时会退回去找 PATH）。窗口启动时会把
>    「仓库根目录 / Rscript / minimap2」写进运行日志。
> 6. **离线 CDS 的「止」按目的序列长度预填**（提示行标明是预填值，可修改；
>    用户改过之后不再覆盖；长度仍须是 3 的倍数）。
> 7. **「变异注释」页会说明缺哪一步**：未开功能注释 / 未勾选「输出变异级明细」/
>    已就绪，三种状态分别给提示，而不是一句固定的"需要勾选…"。
> 8. **看结果更顺手**：「单倍型结果」页表格与序列框之间的**分隔线可拖动**；

>    勾选框，勾上后在右侧列出 `qc.tsv` 里**每个指标**的含义（与是否跑过分析无关）。

```text
`-- _offline\             离线依赖（只有第二个包里有）
    |-- r\R-4.6.1-win.exe
    |-- r-packages\bin\windows\contrib\4.6\
    `-- minimap2.exe
```

## 安装：三步

1. 把压缩包解压到**同一个**、**路径不含中文和空格**的目录，例如 `D:\nanoamp\`。
2. 双击 `install.exe` → 点「开始安装」，等 3–10 分钟。安装位置可改，默认装在
   当前用户目录下（`%LOCALAPPDATA%\nanoamp`），不需要管理员权限；桌面快捷方式与
   PATH 条目默认创建，可取消。
3. 安装完成后双击桌面的「nanoamp 分析工具」（或安装目录里的
   `app\nanoamp.exe`）。建议先点一次 **「环境自检」**，确认 `R version` 是 4.6.x、
   `minimap2` 显示安装目录下的路径。

安装器做的事：选 R（系统里已有 R 4.6 就直接用，否则用随包的 R 4.6，**不动你原有的 R**）
→ 从 `_offline` 装 109 个依赖包（离线）→ 装 nanoamp R 包 → 复制示例注释配置到
`<安装目录>\configs\` → 放好 `minimap2.exe` → 建快捷方式与命令行入口 →
**把 `uninstall.exe` 放进安装目录** → 自检（含 `curl` / 缓存目录 / 示例配置 / 注释可用性）。

## 用法

| 形态 | 适合谁 | 怎么用 |
|---|---|---|
| **GUI** | 不写代码的人（绝大多数情况） | 双击桌面图标；选 FASTQ、目的序列、输出目录（可选填分析名称）→ 开始分析 |
| **CLI** | 批量处理几十上百个样本 | `nanoamp call` / `nanoamp batch`（详见 `02_CLI/README.md`） |
| **R 包** | 嵌进自己的 R 流程 | `run_haplotype_analysis()`（详见 `01_R-package/README.md`） |

三个形态共用同一套分析核心，结果不会互相矛盾。

### 功能注释（可选）

GUI 勾选「功能注释…」，命令行加 `--annotate-config <config.json>`：

- **离线 CDS 路线**：给出 CDS 在**目的序列**上的起止坐标（1-based，两端都算），
  长度必须是 3 的倍数。不需要网络。界面会把「止」按目的序列长度预填（可改）。
- **在线 genome 路线**：什么都不用给；程序自行在 GRCh38 定位扩增子并从 Ensembl
  取转录本结构。建议先点「列出转录本」确认能定位，并可指定具体 ENST。

产物：`annotation.tsv`（每个「单倍型 × 转录本」一行）、`variants_annotation.tsv`
（每个变异一行，`--annotation-detail`）、`transcripts.tsv`（`--list-transcripts`），
以及 `qc.tsv` 与 `run_manifest.json` 里的注释统计。**被跳过的转录本会记账**
（`annotation_skip_reason` / `annotation.skipped_transcripts`），此时退出码仍是 0；
要让流水线把它当失败，加 `--strict`。

### 三种分析模式

| 模式 | 做什么 | 什么时候用 |
|---|---|---|
| **A**（默认） | 参考引导：比对到目的序列，校正测序错误，保留真实变异 | 有明确目的序列时 |
| **B** | 从头聚类（DECIPHER）：不需要参考序列 | 不知道目的序列长什么样 |
| **C** | 原始精确匹配：不做错误校正 | **只作诊断**，比例会明显偏低 |

用仓库里的 E4-3 样本跑模式 A，预期得到：438 条 reads、426 条参与分析、
`mapping_rate 0.9977`、12 种单倍型、目的序列占 31.5%（H2 = 134 条）。

## 卸载

双击 **安装目录里的 `uninstall.exe`**（例如 `%LOCALAPPDATA%\nanoamp\uninstall.exe`）。
它会列出安装目录、桌面快捷方式、PATH 条目、`.Renviron` 行，逐项可勾选，确认后清理：

- **不会删除**：你自己安装的 R、你的 R 库、测序数据与结果文件；
- 随程序安装的 R（`<安装目录>\R\R-runtime`）作为一个可选勾选项出现，默认不勾；
- 从安装目录里运行时，它自己就在要删除的目录中：先删掉其余内容，再在窗口关闭后
  自动删除 `uninstall.exe` 本身与空目录（约 1–2 秒，全程无窗口弹出）。
  安装包里那份不在安装目录内，删除是即时的。

无界面模式：`uninstall.exe --dry-run`（只报告）、`--silent`、`--silent --keep-runtime`。

## 已知限制

1. **依赖 R**：GUI 的 exe 只打包界面（约 11 MB），不含 R 运行时。
2. **exe 冷启动约 1–3 秒**：单文件打包每次运行要解压到临时目录。
3. **GUI 没有批量功能**：批量用命令行的 `nanoamp batch`。
4. **离线 CDS 路线**的坐标要由使用者按自己的扩增子给出（界面会给一个按目的序列长度
   预填的起步值，**不是**真实 CDS 终点）；长度不是 3 的倍数时跳过该注释并记账
   （退出码仍为 0）。
5. **在线 genome 路线**需要访问 Ensembl。扩增子不在内置 gene panel（当前只有 ZNF8）时
   会退化为逐染色体扫描，**可能非常慢**；目的序列与 GRCh38 匹配不足时明确报错，
   不会给出猜出来的坐标；网络不可达时非零退出，不会静默降级。
6. `protein_change` 是 **HGVS 风格**但**未经 HGVS 认证**，不应作为临床报告依据。
   注释结果随 Ensembl release 变化（记录在 `run_manifest.json` 的
   `annotation.ensembl_release`）。
7. **`--aligner r`（纯 R 比对）**的覆盖度/一致度已按真实比对片段计算；该后端比
   minimap2 慢，只有在没有可用 minimap2 时才建议使用。
8. **未在完全无 R 的真机上走查安装器自带 R 的路径**（开发机上始终存在 R）；
   "系统 R 版本不匹配就用自带 R"的决策由 `release/_installer/test_r_version_choice.py` 锁定。
9. **磁盘满、Windows ARM64、高 DPI（125%/150%）**三种环境的实测仍是手工项。
10. **上游（Linux 仓库）回灌未做**：Windows 侧修掉的若干上游缺陷
    （`--no-cache` 语义、无变异标签、Mode B 种子、大响应体截断、R 比对覆盖度等）
    尚未同步回 Linux 仓库。
11. **R 包本体仍是 0.1.0**：R 包的版本号与安装包版本号分开，安装包 0.1.6 里带的是
    当前源码构建的 `nanoamp_0.1.0.tar.gz`（与 0.1.5 相同）。
